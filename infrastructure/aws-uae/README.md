# تجهيز استضافة «نَحْنُ» داخل الإمارات — دون نقل الآن
**الحالة:** تصميم وتحضير فقط — **NOT DEPLOYED** — آخر مراجعة 11 أكتوبر 2026.

## ما أُنجز وما لم يُنجز
- أُعدّت هذه المواصفات وملف بنية تحتية قابل للمراجعة لإعداد شبكة خاصة وقاعدة بيانات PostgreSQL (RDS) ومستودع ملفات خاص (S3). **لم نُنشئ أي مورد AWS، ولم تُحمّل أي بيانات، ولم يتغير DNS.**
- يبقى الموقع العام `na7nlupus.com` على GitHub Pages، وتظل بيانات اختبارات Q-SLAQ الوهمية في مشروع Supabase الحالي خارج الإمارات حتى موعد الانتقال.
- بعد موافقة صاحب المشروع، تُنشأ **بيئة تجريبية منفصلة** للتحقق من البنية والأمان قبل الإنتاج. لا يتم ربط مرضى حقيقيين دون بوابة امتثال مستقلة.
- هذه ليست خطة تشغيل مكتملة؛ تنفيذ واجهة API ونظام هوية بديل، وربط موقع «حسابي»، والتحقق الأمني والتشريعي، وتكاليف AWS الفعلية **ما زالت معلّقة**.

## تحذير الاستقرار الإقليمي (أكتوبر 2026)
أعلنت AWS أن منطقة الإمارات `me-central-1` ما زالت متضررة، وأن بعض موارد منطقة إتاحة واحدة لا يمكن استعادتها، مع عدم ضمان سلامة جميع الخدمات. المرجع: https://health.aws.amazon.com/health/status
**لا تشغّل موارد إنتاجية أو تحفظ بيانات مرضى بهذه المنطقة** قبل استقرار موثق وخطة تعافٍ مجرّبة وموافقة المالك والمختصين؛ وقد يلزم تقييم مقدم استضافة محلي بديل.

## سياسة الانتقال بأقل مخاطر
1. **الآن:** حفظ التصميم في GitHub، إعداد قوائم التحقق، تفعيل حماية حساب AWS والميزانية يدويًا، تحديد مالك البيانات وقواعد الموافقة. **لا تطبيق للبنية.**
2. **بعد تحسن منطقة الإمارات:** مراجعة الخدمات المتاحة والتكلفة وتهيئة حساب AWS منفصل للتجربة، ثم مراجعة وتطبيق قالب CloudFormation مع الموافقة الصريحة.
3. **قبل ربط البيانات:** اختيار مزود المصادقة، بناء واجهة خلفية لا تسرّب مفاتيح الإدارة، وتنفيذ (RLS)/authorization الفعلي واختبار فصل الحسابات؛ إعداد سجل تدقيق ونسخ احتياطية واستعادة مجرّبة.
4. **قبل المرضى:** اعتماد قانوني وأمني مفصل يشمل تصنيف البيانات، مكان كل نسخة ونسخ السجلات ومفاتيحها، معالجات الطرف الثالث، سياسة الحذف والاحتفاظ، الحوادث، موافقة المستخدم، واختبار الاختراق.
5. **بعد موافقة الإطلاق:** نقل تجريبي بدون بيانات حقيقية، ثم ترحيل الحسابات والبيانات المصرح بها فقط، وأخيرًا تبديل الخدمة مع مراقبة وإمكانية عودة.
6. **بعد الاستقرار:** إيقاف التجربة السحابية الوهمية واستبعادها من الإنتاج ومراجعة إغلاق القديم.

## خط الأمان داخل القالب
`DeployInfrastructure=NO` هي القيمة الافتراضية. جميع الموارد مربوطة بشرط **تفعيل صريح** وبأن تكون منطقة AWS `me-central-1`. لا يكفي رفع الملف إلى GitHub لبدء إنشاء موارد. **لا تضبط YES الآن.** تأكد من أن اعتماد التكاليف ووقت الاستقرار واضحان قبل تطبيق أي Stack.

القالب هيكل تأسيسي فقط، ولا ينشر موقعًا أو تطبيقًا أو واجهة API، ولا يمنح شهادة امتثال. عند اعتماد منطقة الإمارات نتحقق من الموارد ونسخها وملاءمتها، ولا نعتمد توفّر Multi-AZ بلا اختبار فعلي. كلمة مرور قاعدة البيانات تُدار بواسطة Secrets Manager؛ لا تُكتب في GitHub.

## ماذا يحتاج المالك أن يفعل الآن داخل AWS؟
- تفعيل MFA للحساب الجذري (Root)، ثم إنشاء هوية إدارية يومية بأقل صلاحيات عبر IAM Identity Center؛ لا ترسل مفاتيح أو كلمات مرور لأحد.
- إعداد **AWS Budgets** وتنبيهات إنفاق تناسب المبلغ الذي تختاره؛ الميزانيات تنبه ولا توقف الموارد تلقائيًا.
- التأكد من بيانات الفوترة ووسيلة التواصل الأمني، ومراجعة إمكانية فصل حساب **Staging** عن **Production** عبر AWS Organizations، بحسب متطلباتك.
- لا تنشئ RDS ولا EC2 ولا ترفع ملفات صحية إلى AWS حتى نحصل على موافقة إطلاق محددة.
